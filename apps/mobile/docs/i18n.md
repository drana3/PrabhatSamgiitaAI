# Interface languages (i18n)

The app speaks **English, Russian and Spanish** (`en`, `ru`, `es`). This is about the interface only:
buttons, titles, menus, settings, messages. It is **not** about song lyrics, meanings or song
translations (those have their own language lists), and nothing here may machine-translate lyrics or
Bába's discourses.

English is the source of truth and the fallback.

## How it works

| Piece | File |
| --- | --- |
| Dictionaries (flat TypeScript objects) | `locales/en.ts`, `locales/ru.ts`, `locales/es.ts` |
| Which strings a native speaker has not read yet | `locales/review.json` |
| Core: `translate`, plural rules, interpolation, fallback, active language | `lib/i18n/core.ts` |
| Numbers, dates, times, file sizes | `lib/i18n/format.ts` |
| `useT()`, `useLanguage()`, plain `t()` | `lib/i18n/index.ts` |
| Device language (`expo-localization`, read lazily, English if absent) | `lib/i18n/device.ts` |
| Persisted choice `auto` / `en` / `ru` / `es`, key `prabhat-language` | `stores/languageStore.ts` |
| Language sheet (Profile, Settings, Language) | `app/language.tsx` |

Resolution: the person's choice, or under `auto` the first device language we support, or English.
A key missing in the chosen language falls back to English (with a dev warning); a key missing
everywhere shows the key itself.

No third-party i18n library: the whole thing is about 300 lines, typed, has no native part beyond
`expo-localization`, and does not depend on `Intl.PluralRules` (which Hermes does not ship on every
platform). `Intl.NumberFormat` and `Intl.DateTimeFormat` are used when present, with a safe fallback.

## Using it

```tsx
import { useT } from "@/lib/i18n"

function Row() {
  const t = useT()                       // re-renders when the language changes
  return <Text>{t("profile.settings.language")}</Text>
}
```

Outside React (stores, `lib/` helpers called from event handlers, alerts): `import { t } from "@/lib/i18n"`.
Plain `t()` reads the language at call time, so:

* do not call it at **module load** (`const LABEL = t("x")` freezes the first language). Make it a
  function, or build the list inside the component;
* a component that renders text produced by a `lib/` helper must still call `useT()` (the return value
  may be ignored) so it re-renders when the language changes.

Keys are typed: `t("nope")` does not compile. If the English string has `{variables}`, TypeScript requires them:

```ts
t("songs.count", { count: 3 })           // plural group songs.count_one / _other (ru: _one/_few/_many/_other)
t("profile.signedInAs", { email })       // "Signed in as {email}"
```

Number variables are formatted for the language (`12 345` in Russian, `12.345` in Spanish). Pass a string to print a number untouched.

Formatting: `formatNumber`, `formatDate(date, "short" | "medium" | "long" | "weekday" | "weekdayShort" | "monthYear")`,
`formatTime`, `formatDateTime`, `formatBytes` from `@/lib/i18n`. Do not write `toLocaleString("en-US")`, month-name arrays
or `${n} MB` any more.

## Adding a string

1. Add the key to `locales/en.ts` (under a sensible group, alphabetical order is not needed).
2. Add the same key to `locales/ru.ts` and `locales/es.ts`.
3. Use it with `t(...)`.
4. `npx vitest run __tests__/i18nParity.test.ts` must pass. It fails if a key is missing or extra in
   any language, a `{variable}` differs, or a plural group lacks a form.
5. `node scripts/i18n/review-sync.mjs` adds the new ru/es keys to `locales/review.json` as unreviewed.

### Key naming

`area.screen.element`, camelCase segments, dots between them, no underscores except plural suffixes:
`tabs.today`, `profile.settings.language`, `player.menu.addToPlaylist`, `songs.empty.title`.
Shared words: `common.*`. Units: `unit.*`. Toasts: `<area>.toast.<what>`. Accessibility labels: `<key>.a11y`.
Name the **role**, not the wording (`profile.signOut`, not `profile.signOutButton` and not `profile.logout`).
Never build a sentence from pieces (`t("a") + " " + t("b")`): word order differs per language. Use one string with variables.

### Plurals

A counted string is a group of keys sharing a base name and the variable `{count}`:

```ts
// en.ts and es.ts: one + other
"songs.count_one": "{count} song",
"songs.count_other": "{count} songs",
// ru.ts: one + few + many + other
"songs.count_one": "{count} песня",     // 1, 21, 101
"songs.count_few": "{count} песни",     // 2-4, 22-24
"songs.count_many": "{count} песен",    // 0, 5-20, 25-30
"songs.count_other": "{count} песни",   // fractions only
```

The required forms per language are in `REQUIRED_PLURAL_FORMS` (`lib/i18n/core.ts`); the parity test enforces them.
Spanish: write "uno / otros" like English. When a sentence has no number ("No songs yet") it is not a plural group.

## Adding a language

1. Add the code to `Language` / `LANGUAGES` / `LANGUAGE_NATIVE_NAMES` / `LOCALE_TAGS` / `REQUIRED_PLURAL_FORMS` and a rule in `pluralForm` (`lib/i18n/core.ts`).
2. Create `locales/<code>.ts`, register it in `locales/index.ts` and `app/language.tsx`.
3. Translate every key (the parity test lists what is missing), add the language to `locales/review.json` and `__tests__/i18nParity.test.ts` (`review.json` check).
4. Check the layout at 390 px: Russian and Spanish run 20-30 percent longer than English.

## What is never translated

* **Song titles**, lyrics, meanings, Bába's discourses. Never machine-translate these.
* **Sanskrit and Bengali terms** (`Sádhaná`, `Bábá`, `mantra`, `Ananda Marga`, raga and tala names), kept as in the sources.
* **"Prabhat Samgiita"**: always this Latin spelling, in every language.
* **Kiirtan / Bhajan**: in English text **Kiirtan** with two i's (also Spanish: `Kiirtan`, `Bhajan`). In Russian: `Киртан`, `Бхаджан`.
  Never `Kirtan`, never `Kiertan`. The parity test checks the spelling.
* Code identifiers, route names, file names (`kirtan-player`, `kirtanStore`) keep the old spelling.
* Names of languages in the language sheet: each in its own script (`English`, `Русский`, `Español`).

## Register

Russian: formal «вы», natural phrasing, no word-for-word calques ("Сохранить в..." not "Спасти к..."), «ё» only where it changes meaning. Spanish: informal «tú», neutral (understood in Spain and Latin America), no «vosotros». Every ru and es string starts unreviewed in `locales/review.json`; a native speaker flips it to `true`.
